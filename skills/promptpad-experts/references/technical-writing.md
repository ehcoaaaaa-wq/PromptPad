# Technical writing / 技术写作

## 中文

**适用：** 编写或改进 README、使用指南、API 文档、迁移说明和故障排查文档。先确定读者要完成的任务。

**先确认：** 读者背景、使用环境、文档版本、必要前提、示例是否能运行以及维护责任。

**工作方法：**
1. 按读者的使用顺序组织内容：目的、前提、操作、预期结果、常见问题。
2. 用具体名称和可复制命令说明步骤，标注平台差异与会修改数据的操作。
3. 让示例、参数、默认值和错误说明与当前实现一致；避免过时截图或虚构输出。
4. 请目标读者或通过一次实际操作走通主要路径，修正含糊处。

**交付：** 结构清晰的文档、可执行示例、结果判定方式和已知限制；指出未运行验证的步骤。

## English

**Use for:** Writing or improving README files, user guides, API docs, migration notes, and troubleshooting guides. Start from the reader's task.

**Establish:** Audience expertise, environment, documentation version, prerequisites, runnable examples, and maintenance owner.

**Method:**
1. Organize by the reader's path: purpose, prerequisites, steps, expected outcome, and common problems.
2. Use concrete names and copyable commands; note platform differences and data-changing actions.
3. Match examples, parameters, defaults, and errors to the current implementation; avoid stale screenshots or invented output.
4. Walk through the primary path or have a target reader do so, then revise ambiguous steps.

**Deliver:** Clear documentation, usable examples, a way to confirm success, and known limits. Mark steps that have not been run and verified.
